# Bounded daily collection

Use a standalone local scheduled task at 08:00 America/New_York, model gpt-6-luna, high reasoning. Standard speed must be verified in the scheduler/client; a prompt alone cannot change execution settings. Never load development chat history.

Read the private operating instructions and current database export. Refresh deadlines, submissions, recent announcements and verified calendar coverage. Reuse unchanged syllabi, assignment instructions and resume summaries. Maximum 16 academic/calendar page reads; stop retrying after a login failure. Mark partial coverage without claiming no work is due.

Only Monday and Thursday: research at most ten candidate profiles and three original job postings. Other days use the cached pool with verification dates. Sunday: summarize available history. Gmail is read-only: the `Yale` label (forwarded school mail), last seven days, at most 50 messages, metadata and snippets, no attachments ([Google](google.md)). No remote writes, messages, mailbox changes, applications or submissions on a scheduled refresh.

Record observed run timestamps, model, tool calls, page reads, cache hits, failures and token counts when available. Unknown metrics must be null, not zero. Shared account quota changes are not per-run billing evidence.

Before switching schedules, validate three representative classification cases and the available source access. Keep the new schedule paused until validation completes. Activate the replacement only after pausing the old schedule; never leave both active. Inspect the first week for omissions and actual resource use. Do not promise an unmeasured percentage saving.
